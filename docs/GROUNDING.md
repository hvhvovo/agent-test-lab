# 引用合法，经历仍可能被编造

复现输入：`尚未做过 RAG，只学习过概念。`
模型输出：`你在 RAG 项目中如何优化召回？`，引用 `demo:1`。
引用ID确实来自检索，因此原有结构/引用校验会放行。错误在于问题预设了用户已有项目经历。

```bash
python -m scripts.reproduce_grounding
python -m pytest tests/test_grounding.py -q
```

这是注入固定模型响应的可控故障重放，不是真实供应商已观察到的线上事故。

## 处理

1. 保留结构和引用ID校验，未知ID仍直接拒绝。
2. 记录工具实际返回的文本；只用这些文本进行检查。
3. 引用含否定、计划、团队归属或注入提示时，根据原题主问题识别细分主题，替换为同主题的假设场景，清空引用。
4. 无引用且明显预设个人经历的题也降级；通用知识题保留。
5. 将规则版本和触发原因放在 `grounding_guard` 字段。去重后可能不足原题数。

整题替换包含追问和考察点，避免主问题改了，追问仍编造经历。代价是丢失部分有价值的个性化问题。

## 无法保证的部分

这是词法防线，不能证明语义忠实。`并非没有做过`可能误拦；`实践经验还是空白`可能漏检；真实引用也可能包含错误数字或其他人的贡献。挑战集明确保留这些反例，不把已知漏检删掉来提高指标。

## 真实模型配对评测

设置环境变量后运行（有API费用）：

```bash
python -m scripts.evaluate_llm --live --repeat 3
```

24个合成样例，每例3次，共72次Agent任务；每次最多5轮模型交互。先用 `--repeat 1`检查费用和兼容性。默认关闭网络调用；缺少配置会在开始前退出。

结果写入本机 `reports/live-grounding-时间.json`，包含模型名、时间、代码与数据集哈希、温度、轮次、耗时、工具轨迹、原始题和降级后的题。不会保存密钥或服务地址。失败调用可能已经产生费用，token统计不是完整账单。异常中断保留已完成结果。

同一原始输出应用防线前后比较，可隔离后处理效果；不是分别请求两次模型的独立A/B实验。对每行按 `criterion` 判断，填写 `review.raw` / `review.guarded` 为 JSON `true` 或 `false`，并说明证据。未评审保持 `null`。

```bash
python -m scripts.evaluate_llm --summarize reports/live-grounding-实际时间.json
```

汇总显示请求失败率、已评分数、待评分数和已评分通过率。请求失败不进入语义评分分母，但必须单列；不得把未评分算通过。降级比例用于观察质量与个性化的取舍。三次重复只能提供初步波动信息。

## 数据可信度

8条开发样例和16条挑战样例全部是项目内编写的合成数据；挑战集也不是独立盲测。现有检索标注集保持不变，防止这次改动污染其对比口径。

下一步由另一位评审自行编写材料与查询，提供使用许可，脱敏后再加入独立文件。样例至少包含同义表达、否定、时间变化、主体归属、长文档和无答案。两人独立评分后记录分歧与裁决。现在没有这些真实材料和外部评分，不能声称已完成独立验证。

本机评测输出默认不提交，真实资料尤其不能直接推送。需要分享结果时，仅导出脱敏样例、匿名评分和聚合指标。

## v2：降级保留主题

旧版根据JD选题再按位置轮换，因此“优化召回”会变成“资料注入”。新版使用 `app/topics.py` 的27个固定主题路由，以原题主问题为输入；追问与资料中的文本不参与主题选择。唯一最高关键词得分才认定主题，平分或无命中都标记 `unclassified`，返回需求澄清题，不随意跳到别的专业题。

召回质量使用专门的假设场景模板，保留构建标注集、定位遗漏原因、比较指标与延迟等追问。其他已识别主题使用对应题库模板。整个问题、追问与考察点一起替换，引用清空；重复替代题去重，因此最终题数可能减少。

规则仍可能因多义词错误分类，不能声称主题保持率100%。`grounding_guard` 记录主题、模板ID和规则版本。原题未经处理直接拼到“假设”后可能继续保留错误前提，因此不采用这种拼接方法。

真实评测新增 `topic_preserved` 人工评分项：仅在确实发生降级时，对比原题与替代题的主要考察目标，填写 true/false；未降级或未评审留 null。汇总只计算已评分部分，和经历依据通过率分别报告。代码还记录主题路由与题库哈希，便于复现。
